- **N15:2** (definition, A, module, person) Strong code ownership assigns each module to one developer who alone may change it; weak ownership lets others change modules while owners take responsibility and keep an eye on changes; collective ownership, from Extreme Programming, lets anyone change anything. Source: Fowler 2006. From: [Strong, weak, collective: the named models](../ownership-and-accountability-for-delegated-work.md#strong-weak-collective-the-named-models).

- **N15:4** (argument, A, team, person) Four ownership models sit on a scale from one individual owning the whole system to collective ownership; no single code ownership model is best and the model should be adjusted over the phases of a unified-process project. Figures: 45 citations recorded in OpenAlex; abstract only. Where: over the phases of a unified-process project. Source: Nordberg 2003. From: [Strong, weak, collective: the named models](../ownership-and-accountability-for-delegated-work.md#strong-weak-collective-the-named-models).
- **N15:5** (practice, A, team, person) Collective ownership is an obligation, not a permission: anybody who sees an opportunity to add value to any portion of the code is required to do so at any time, and everybody takes responsibility for the whole of the system. Where: at any time. Source: Beck 2000. From: [Strong, weak, collective: the named models](../ownership-and-accountability-for-delegated-work.md#strong-weak-collective-the-named-models).
